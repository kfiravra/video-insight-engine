<domain_schema name="learning">
LEARNING DATA — LearningData schema

Extract structured educational content.

{
  "keyPoints": [
    {
      "emoji": "single emoji matching the topic",
      "title": "Clear, specific title (not 'Important Point' but 'Redis Caching Reduces DB Load by 90%')",
      "detail": "2-3 sentences with specific details — numbers, names, quotes, examples from the video",
      "timestamp": null
    }
  ],
  "concepts": [
    {
      "name": "Term as the speaker uses it",
      "emoji": "relevant emoji",
      "definition": "Speaker's explanation, not a textbook definition",
      "example": "Example from the video or null",
      "analogy": "Analogy from the video or null",
      "group": "Short thematic group this concept belongs to (e.g. Foundations / Mechanics / Applications)",
      "connections": [
        {"to": "EXACT name of another concept", "type": "causes | requires | contrasts | partOf | relatesTo"}
      ]
    }
  ],
> UI: Concepts → ConceptCanvas tiered graph explorer (grouped lanes + typed edges) when connections are populated; otherwise falls back to FlashDeck flip cards.
> REQUIRED: every concept MUST list 1-3 `connections` to other concepts in this same `concepts` array. Each connection is an object: `to` is the EXACT NAME of the other concept, `type` is the relationship the speaker draws — `causes`/`requires` (X drives or depends on Y), `contrasts` (X is opposed to / a trade-off against Y), `partOf` (X is a component of Y), or `relatesTo` (loose association). These typed connections are the spine of the concept_canvas — without them the canvas renders disconnected dots. If no other concept legitimately connects to this one, leave the array empty and the fallback layer routes to flash_deck.
> GROUPING: assign every concept a short `group` label — aim for 2-5 thematic groups across the whole list (e.g. Foundations / Mechanics / Applications). Keep ≤16 concepts on the canvas; when the video is richer, group tightly rather than listing more disconnected terms.
  "takeaways": [
    "Actionable conclusion starting with a verb: Use..., Implement..., Avoid..."
  ],
  "timestamps": [
    {
      "time": "M:SS or H:MM:SS",
      "seconds": 0,
      "label": "Descriptive label for this moment"
    }
  ],
> UI: Timestamps → MomentTrack items (navigation points — no endSeconds). Fill seconds for playback jump links.
  "keyQuestion": "Central question this video answers",
  "summary": "2-3 sentence summary of the core teaching"
}

// Example for a 15-minute explanation video:
{
  "keyPoints": [
    {"emoji": "🧠", "title": "Compound interest works both ways", "detail": "Not just savings — debt compounds too. A $5,000 credit card balance at 24% APR becomes $6,200 in one year without payments.", "timestamp": 145}
  ],
  "concepts": [
    {"name": "Time value of money", "emoji": "💵", "definition": "A dollar today is worth more than a dollar tomorrow because you can invest it. The speaker uses the example: '$100 invested at 7% doubles in ~10 years.'", "example": "$100 invested at 7% doubles in ~10 years", "analogy": null, "group": "Foundations", "connections": [{"to": "Compound interest", "type": "causes"}]}
  ]
}

COMPLETENESS:
- Cover the full video chronologically — don't cluster points from the first 10 minutes

RULES:
- keyPoints teach one specific thing each — no filler
- Concepts: only include what's actually explained in the video
- Takeaways: be specific ("Use Redis for session storage to handle 10x more concurrent users")
- Timestamps: cover introduction, topic changes, demos, conclusions
- Preserve speaker's terminology and examples exactly
