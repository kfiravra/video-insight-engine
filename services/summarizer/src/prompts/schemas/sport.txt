<domain_schema name="sport">
SPORT DATA — SportData schema

Extract structured sport / match-analysis / highlights content.

THINKING GUIDE:
- Sport content covers a MATCH or a player/team analysis. The value is the
  sequence of key events, who lined up where, and how the numbers compare.
- Match events are the chronological backbone: goals, cards, substitutions,
  turning points. Set a timestamp so the viewer can jump.
- The formation is the lineup laid out by position — players as nodes on a
  pitch. This is the sport signature — a read-only tactical diagram.
- The stat comparison weighs two teams or players on the same metrics.

{
  "title": "The match / analysis in one line, or null",
  "matchEvents": [
    {
      "label": "What happened (goal, card, sub)",
      "description": "1 sentence of detail",
      "timestamp": 0
    }
  ],
> UI: matchEvents → MomentTrack. Set timestamp (seconds) so viewers jump to each event.
  "formation": {
    "name": "Formation shorthand (e.g. 4-3-3), or null",
    "team": "Team name, or null",
    "positions": [
      {
        "player": "Player name",
        "role": "Position label (GK, RB, CM, ST)",
        "x": 50,
        "y": 90,
        "number": 9
      }
    ]
  },
> UI: formation → FormationDiagram. positions place players on a pitch. x/y are 0-100 percentages: x = left→right (0=left touchline, 100=right), y = own goal→opponent goal (0=own goalkeeper end, 100=attacking end). number is optional shirt number.
  "statComparison": {
    "leftLabel": "Team / player A",
    "rightLabel": "Team / player B",
    "comparisons": [
      {
        "feature": "The metric (possession, shots, xG)",
        "left": "A's value",
        "right": "B's value"
      }
    ]
  }
> UI: statComparison → Comparison. Two sides on the same metrics; each side ≤ 80 chars.
}

RULES:
- formation.positions x and y MUST be 0-100. A player with no clear position is
  omitted, not stacked at 0,0.
- Preserve exact scores, stats, and minutes; do not round figures.
- matchEvents timestamps must be ascending, in seconds.
- statComparison needs BOTH sides on every row — drop a metric if one side is unknown.

COMMON MISTAKES:
- Inventing positions the video never shows — only place players you can place.
- Treating the stat comparison as a flat list — it is two sides, same metrics.
- Putting commentary in matchEvents — events are concrete things that happened.
