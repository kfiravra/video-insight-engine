**Arithmetic and sources**

**L1 — outline from the plan instead of memory**
- Recorded on v9 prod (`g3-prod-benchmark.json`): the memory call takes 7.0–9.2 s, outputs 719–1,028 tokens and
  costs $0.0092–0.0116. The hero lands at memory-done (11.4–15.6 s). The plan writes 765–991 tokens in 19.1–23.8 s,
  about 39–43 tok/s.
- Hero: it would move to plan-done, +10–17 s per run (plan-done − hero on the 6 runs with memory).
- Plan wall: if all of the memory's output moved into the plan, the plan grows by 719–1,028 / 39–43 = +17–26 s.
  The outline's share of that output is not recorded, so this is an upper bound. The provisional tab and every text
  group would move by the same amount.
- Cost: the memory call saves −$0.009–0.012. The moved output costs 719–1,028 × $15/MTok = +$0.011–0.015. Net ≈ 0.
- Verdict: worse latency, no saving.

**L2 — slice long videos by brief ranges**
- Recorded: no run over 40 minutes in g0–g3, so the chunk × group path (3.7) was never measured (g3 Q-long).
- On the benchmarks, every group reads the transcript from the cached prefix, 7,494–10,214 tokens per call (`cr`).
  At $0.10/MTok that is ≤ $0.001 per group call. Output tokens set the latency and do not change (brief principle 1).
- Projection: ≈ 0 s and ≤ $0.001 per group call on ≤ 20-min videos; — over 40 minutes.
- Cost: groups would no longer read the full transcript, which breaks principle 1.

**L3 — 720p vision**
- Recorded: the D3 measurement (1d.4, dev, 2 videos; tasks.md log 2026-10-08).
  - 720p reads uC45's card text 5/5, against 0/5 at 360p.
  - It adds 3–10 s per vision pass and costs more than the v8 vision baseline (jMq8 $0.149); 360p costs $0.098.
  - Image tokens: about 1,000 per frame at 720p vs 314 at native 360p (A-DIGEST §4).
- Cost: +686 tokens/frame × 40 frames (HIGH) × $3/MTok = **+$0.082/run**. For 8 frames (STANDARD): +$0.016.
- Latency: +3–10 s on every v9 run with frames, because frames-done gates `complete` on all 5 of them (§3.3).

**L4 — `WORKER_CONCURRENCY=2`**
- Recorded:
  - Prod runs `WORKER_CONCURRENCY=1` (A-DIGEST §4). Queue waits were 6.7–18.0 min in the 2026-10-05 v8 batch (A4).
  - A v9 run with frames takes 59.3–92.8 s (g3 §Prod).
  - Scene detect and scoring saturate the box (t3.xlarge, 4 vCPU = 2 cores) for 20–40 s per run (A-DIGEST §Box).
  - Rate limits have more than 12× headroom; 0 × 429.
- A second video that arrives during a run waits up to one run (59–93 s); with two consumers it starts at once. The
  first video can lose up to the overlapping CPU-bound 20–40 s.
- Single-video latency and cost per video are unchanged.

**L5 — 1h cache TTL at traffic**
- Plan: the static half is 16,290 tokens. A 1h write costs $0.0977, a read $0.0049, uncached $0.0489 (g2 §Cache
  prices; g3 §Prod token count).
  - The g3 prod window was 7 runs in 17 min: 1 write + 6 reads = **$0.127**, against 7 × $0.0489 = $0.342
    uncached → **−$0.031/run**.
  - If plans run more than 1 h apart, every plan writes: +$0.049/run vs uncached.
  - Break-even: 1 write + n reads ≤ (n + 1) × uncached needs n ≥ 1.1.
